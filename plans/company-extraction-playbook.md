# 公司专属提取逻辑实战手册（以平安产险为例）

- 适用范围：STEP1 页码定位 → STEP2 规则法提取 → STEP3 标准化
- 首个样板：平安产险 2022–2025
- 后续接入其他公司时，按本文的排查方法、代码约定和验收标准执行

---

## 1. 三层架构：通用规则 → 公司 YAML → 公司专属 extractor

```
config/extraction/tables.yaml              表级定义（所有公司共用）
  ↓
config/extraction/companies/<公司>.yaml    公司级规则（页码窗口、锚点、extractor）
  ↓
services/company_extractors/<公司>.py      版式特例后处理（可选）
```

| 层 | 解决什么 | 不解决什么 |
| --- | --- | --- |
| 通用规则 | 大多数公司的常见版式、边界、表头识别 | 合并单元格、跨章节指标、无表头续页 |
| 公司 YAML | 页码窗口、标题变体、必填行、结构版本 | 行列错位、数值粘连 |
| 专属 extractor | 版式层面的修补（拆列、补行、改标签） | 指标语义匹配（交给 STEP3） |

**原则**：能用 YAML 解决的不要写 Python；只有“数据在 PDF 里但网格结构坏了”才写 extractor。

## 2. 平安 2022–2025 遇到的问题与修复

### 问题 1：金额两列被合并成一个单元格

- **现象**：认可资产 = 0，上季度末 = `5.0456e15`（异常大数）
- **原始行**：`['认可资产', '', '50,456,00551,044,518', '49,065,744']`
- **根因**：pdfplumber 把“本季度末数/上季度末数”识别成一列，第 2 列留空
- **修复**：`_split_merged_numbers()` 按数字模式拆分（支持金额、负数、百分比）
- **注意**：拆分后若前一列是空占位，要**用第一个值填掉空列**，否则整行多一列、全部错位

### 问题 2：行标签被换行拆成两列

- **现象**：`核心一级资本` 识别不到，整行数值错位
- **原始行**：`['核心一', '级资本', '10,119,26610,653,295', '10,166,595']`
- **修复**：`_fix_solvency_main()` 先合并前两列中文标签（`_looks_like_label` 判断无数字），再拆金额
- **注意**：表头行必须跳过合并逻辑，否则 `类型 + 本季度末` 会被拼成一列

### 问题 3：表头本身被合并

- **现象**：2023 认可资产“本季度末”被识别成“上季度末”
- **原始表头**：`['类型本季度末', '上季度末', '下季度末(预测)']`（3 列 vs 数据 4 列）
- **修复**：`_fix_solvency_header()` 把首列拆成 `类型 + 本季度末`
- **注意**：这类问题不会报错，只会静默错列；必须逐行核对首年数据

### 问题 4：经营表只识别出前 13 行

- **现象**：综合成本率、费用率、签单保费全缺
- **根因**：pdfplumber 在 2022 的第 17 页只认出“1.主要指标”那块，后续效益/规模/品质类没有线框
- **修复**：`_complete_operating()` 用 PDF 文本行重建“标签 + 本季度 + 累计”，按标签去重合并
- **注意**：文本解析要跳过分组标题（`1.主要指标`）、单位行、章节标题，避免把正文段落当指标

### 问题 5：经营表首行是分组标题，表头丢失

- **现象**：2024/2025 经营表 header = `['1.主要指标', '', '']`
- **风险**：期间识别依赖默认值，换年份容易错列
- **修复**：`_normalize_operating_rows()` 统一补 `['指标名称','本季度数','本年度累计数']`，并清理分组标题、`--` 占位行
- **注意**：该函数必须幂等，2022/2023 已经是标准表头时不能重复插入

### 问题 6：签单保费不在经营表里

- **现象**：经营表只有“保险业务收入”，签单保费缺失
- **根因**：平安把签单保费放在下一页“公司分类”表（`2022 年度的签单保费（万元）`）
- **修复**：`SIGNED_PREMIUM_RE` 从 `page+1` 提取并追加到“本年累计数”列
- **注意**：2024/2025 签单保费已并入经营表，追加前先判断是否已存在，避免重复

### 问题 7：LCR 标签顺序与标准库相反

- **现象**：流动性覆盖率全部未匹配
- **报告写法**：`基本情境下，未来3个月LCR1`
- **标准库**：`LCR1未来3个月`
- **修复**：`_fix_liquidity_rows()` 用正则重排为 `LCR1未来3个月`
- **效果**：LCR1/2/3 × 3M/12M 六个编码全部有值

### 问题 8：期间口径两套并存

- **现象**：同一指标有“本季度数”和“本季度末数”两套，STEP7 分列
- **修复**：`solvency_normalizer._normalize_period_alias()` 全局统一：
  - 本季度数 / 本季度 / 本期 → **本季度末数**
  - 上季度数 / 上季度 / 上期 → **上季度末数**
- **注意**：这是全局口径变更，历史窄表需重新标准化；`test_new_workflow_behavior` 的期间断言已同步

### 问题 11：经营表后半段丢失（无表头/编号标签/换行）

- **现象**：不同公司的经营表只提取到“1.主要指标”前半段，费用率/赔付率/签单保费子项缺失
- **共性**：pdfplumber 只识别出部分表块；文本层里标签带“（一）/1./3.1”，且换行拆词
- **修复**：`_operating_table.complete_operating_tables()` 对所有公司统一补全：
  - 起点兼容“指标名称/项目/主要经营指标”，无表头时回退到关键指标附近
  - 清洗编号前缀、合并换行标签、保留 `--` 占位值
  - 按清洗后标签去重，原有行优先
- **设计取舍**：不逐家确认是否存在该问题，直接对全量公司冗余执行；标准化只匹配已知指标，
  多余行会进入未映射/诊断，不会污染标准数据

### 问题 10：财险公司“寿险业务保险风险最低资本合计”恒为 0

- **现象**：部分报告写 `-`，部分公司整行不披露，标准化后缺失，STEP7 误判缺指标
- **口径**：`INSURANCE_RISK_CAPITAL` 对财险公司恒为 0
- **修复**：STEP3 末尾 `_fill_insurance_risk_zero_default()` 按同表最低资本子项的期间补 0，
  备注“财险公司寿险业务保险风险最低资本恒为0”；已有值不重复
- **注意**：仅对财险 Profile 生效，寿险 Profile 不补

### 问题 9：`--` 占位符导致费用率/赔付率整行丢失

- **现象**：平安 2025 经营表有“综合费用率 27.0%”，但标准化后 `EXPENSE_RATIO` 为空
- **根因**：文本重建时把 `--` 当作非数值，标签行收集不到值就跳过；`--` 又被当成下一行标签，累计值挂到 `--` 上，随后被清理
- **修复**：`_is_value_line()` 把 `--`/`-`/`—` 视为合法占位值，继续收集累计列
- **效果**：平安 2024/2025 补齐综合费用率、综合赔付率、手续费及佣金占比、业务管理费占比

### 问题 9：数值单位随年份变化

- **现象**：2022/2023 主表单位是万元，2024/2025 是元
- **处理**：extractor 不改单位，交给 STEP3 的 `_source_unit` + 默认“元→万元”换算
- **验证**：认可资产 2022 为 50,456,005 万元，2024 为 54,385,130 万元，跨年量级连续
- **注意**：不要在公司配置里写死 `unit`，否则换年份会误判

## 3. 排查方法（固定套路）

### 3.1 逐层看数据，不要直接看最终指标

```
定位结果（页码 + rule_note）
  → 每张表的 rows（表头 + 前 20 行）
  → 标准化后的关键指标（编码/期间/数值/来源页）
  → diagnostics（未匹配/值为空/口径冲突）
```

现成脚本（`tmp/`，本地调试用）：

```bash
# 单年细节
PYTHONPATH=. ./venv/Scripts/python.exe tmp/inspect_pingan.py 2024

# 四年一致性
PYTHONPATH=. ./venv/Scripts/python.exe tmp/compare_pingan_years.py
```

### 3.2 判断“缺失”属于哪一类

| 现象 | 归属 | 处理 |
| --- | --- | --- |
| 行在 rows 里、值正确，但指标没出现 | 标准化匹配 | 改行标签映射 / 补 taxonomy 别名 |
| 行在 rows 里、值是 `-` | 源表未披露 | 保持缺失，不写 0（资本明细除外） |
| 行不在 rows 里、PDF 里能看到 | 提取层 | extractor 重建该表 |
| 整张表定位不到 | 页码/锚点 | 改 YAML 的 `expected_pages` / `anchor_terms` |
| 值存在但为 0 | 空白按 0 口径 | 核对源表，确认是“-”还是空白 |

### 3.3 跨年对比的固定口径

- 以最新完整年份为基准（本次 2024）
- 对比“标准编码集合”，不用记录数（记录数受期间列数影响）
- 差异必须能归因到：**报告披露变化** / **提取失败** / **匹配失败**
- 0 值单独列出来核对，不能默认正确

## 4. 新公司接入 SOP

1. **跑定位**：`locate_one_pdf_bytes`，确认 6 张目标表页码在合理范围
2. **写公司 YAML**：`expected_pages` + `tolerance: 2` + `anchor_terms`；先只配经营表，跑通再补全
3. **看 rows**：逐表打印表头 + 前 20 行，重点检查：
   - 表头列数与数据列数是否一致
   - 行标签是否被拆成两列
   - 数值是否粘连
   - 首行是不是分组标题
4. **看标准化结果**：目标编码是否有值、期间是否正确、诊断里未匹配的原始项目
5. **写 extractor**（只有第 3/4 步发现版式问题才写）：
   - 在 `services/company_extractors/` 新建模块，`@register("<name>")`
   - YAML 加 `company.extractor: <name>`
   - 只改 `rows` 和 `table_blocks`，不碰标准化
6. **同步 blocks**：STEP3 优先读 `table_blocks`，只改 `rows` 不生效
7. **跑 3 年**：至少覆盖“早期 + 最近”，确认同一套逻辑不依赖单年版式
8. **写文档**：把本公司的特例补到本文件第 2 节的同类问题下

## 5. 代码约定（写 extractor 必须遵守）

| 约定 | 原因 |
| --- | --- |
| 函数签名 `postprocess(tables, *, pdf_bytes)`，用 `@register("name")` | 与 `apply_company_extractor` 对接 |
| 只修改 `table.rows` 与 `table.table_blocks`，不改 `table_config` | 配置归 YAML 管 |
| 每个修复都幂等（重复执行结果不变） | 批量重试/多表块会重复调用 |
| 异常不要吞掉，交给 `extract_document_tables` 统一记录 | 失败要能在 STEP2 日志看到 |
| 文本解析要设停用词/长度上限 | 避免把正文段落当指标 |
| 标签清理后保留原文顺序 | 标准化按行顺序处理期间列 |
| 不要写死年份/页码 | 页码在 YAML，版式差异用正则/结构判断 |

## 6. 验收标准（每家公司必须全过）

- [ ] 目标表全部定位（该年报告没有的表除外，需注明原因）
- [ ] 每张表 rows 的表头列数 = 数据列数
- [ ] 关键指标数值与 PDF 原文逐项核对（至少：认可资产/负债、实际资本、最低资本、保费、净利润、成本率）
- [ ] 跨年编码集合差异可归因（披露变化 / 应缺）
- [ ] 0 值记录逐条核对（是否源表 `-` 或空白）
- [ ] 期间口径只有：本季度末数 / 上季度末数 / 下季度末预测数 / 本年累计数（+ 近三年平均）
- [ ] `keep_unmapped=False`（正式口径）下目标指标无回归
- [ ] `py_compile` + 相关回归测试通过

## 6.5 单文件与批量路径的一致性

两条路径必须共用同一个入口，否则同一年份在 STEP2 单文件上传和批量处理里会得到不同结果。

| 路径 | 入口 | 应用位置 |
| --- | --- | --- |
| 批量 | `batch_workflow.extract_document_tables` | 表组装完成后 |
| 单文件 | `ui/step2_extraction.build_tables_from_page_results` | 返回前（含单表重提取） |

- 共用函数：`services.company_extractors.apply_company_extractor_for_tables()`
- extractor 名称来源：优先读 `PageMatch.table_config["_extraction_rule"]["extractor"]`；从工作流配置恢复时用 `resolve_rule(封面公司, 年度)` 现场解析
- 单文件日志会出现一行 `目标表=公司专属规则 / 识别方式=extractor:pingan`，失败时保留通用结果
- 单表“重新提取”走同一 build 函数，因此也会重新应用 extractor

**勾稽检查（STEP4）注意点**：

- `solvency_validator.PERIOD_GROUP_ALIASES` 把“本季度末数”归入 `当前期末` 组、“上季度末数”归入 `上期末/期初` 组；期间口径统一后不需要改检查逻辑
- extractor 只修 `rows` / `table_blocks`，不产生新的指标编码或期间，校验结果不会因接入而变化
- 实际运行时仍会出现两类**既有**告警（与 extractor 无关，人保等未接 extractor 的公司同样存在）：
  1. `SCHEMA_ALLOWED_PERIOD`：偿付能力主表的“下季度末预测数”、经营表的“本年累计数”不在部分指标字典的允许期间内
  2. `COMBINED_RATIO` / `CORE_RATIO` 等式勾稽：主表金额为万元整数，比率四舍五入后与披露值相差 0.01–0.05 百分点，超过当前 0.0001 容差

## 8. 已知限制

1. **专属 extractor 单文件与批量共用同一入口**（`batch_workflow.extract_document_tables`），STEP2 单文件上传同样生效。
2. 平安 2022 无可提取的“近三年投资收益率”独立表，2023 起才有。
3. 目标指标无值清单里的 `LOSS_RATIO` / `EXPENSE_RATIO` 等：报告只披露综合成本率，未拆分子项，属应缺。
4. 部分 ANC/POLICY_SURPLUS 明细在报告中为 `-`，按资本明细空白=0 口径处理，需人工确认。
5. 文本重建的经营表依赖 PDF 文字层，扫描版报告需走视觉法。
6. **行次不参与指标消歧**：指标字典只按标签文本匹配。`2.4 / 3.8 / 4.3 减：超限额应扣除的部分`、`1.2.4 递延所得税` 这类与别处同文但行次不同的行，会保持未映射（`RAW_`）并在匹配诊断中可见；不要靠猜行次强行补映射，否则会破坏下游按“编码+期间”合并。
7. **公司可覆盖全局表签名**：公司 YAML 的 `tables[].signature_terms` 优先于 `config/extraction/tables.yaml` 的全局签名（显式 `[]` 表示清除），用于“综合退保率 / 季均融资杠杆比例”这类公司版式差异；未配置时行为不变。配套的 `start_item/end_item` 只在已选页 ±1 内做边界闭合，避免全文档重扫误命中管理层小表。
8. **STEP3 缺口双通道可见**：批量 STEP3 页面在下载按钮上方提示缺口条数/公司数/覆盖率；导出的 Excel 在 4 个基础工作表后追加 `缺失指标清单` 与 `公司覆盖汇总`，口径与 STEP7 必需期一致（`require_expected_period=True`）。
9. **扫描版页面**：无文字层的表（如诚泰 2022 的四张表）规则法无法提取，只保留可读表；批量流程默认不自动转视觉大模型，需要时在 STEP2 手动切换。
10. **整本扫描件自动转大模型**：STEP1 定位时若判定文档为 SCANNED（文字页占比 ≤30%），即使选择规则法也会自动改走 `hybrid` 定位，并在说明里标注“扫描版自动转视觉大模型识别”；未配置模型接口时只给提示、不改变结果（如太平科技 2025）。配置入口在页面侧栏的大模型设置。
